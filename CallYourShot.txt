Build a polished, responsive web app called “Call Your Shot,” a personal prediction journal that learns from a user’s past predictions.

CORE USER FLOW
1. The user creates a prediction with:
   - Event or question
   - Category: sports, markets, elections, culture, or other
   - Their prediction
   - Reasoning
   - Confidence from 1 to 5
   - Optional event date
2. The app saves it and displays it in the dashboard and history.
3. After the event, the user marks the prediction correct, incorrect, or unresolved and can add an outcome note.
4. On later predictions, the app retrieves relevant previous picks and displays a concise insight based only on that evidence. Example: “You’re 4/5 on underdog picks” or “Your confidence 5 picks have been correct 2/6 times.” Show the supporting past picks and sample size. If there is not enough history, clearly say that.
5. The dashboard shows total resolved picks, accuracy, recent picks, and useful category/confidence patterns. Do not present a pattern without enough supporting data.

WALRUS MEMORY
Design a dedicated memory service layer for Walrus Memory. Store a memory when a pick is created and another memory when it is resolved. Retrieve relevant memories before generating an insight. Make the memory integration real and configurable through environment variables; do not hardcode secrets or pretend a memory was saved if the service call failed. Show memory status to the user and handle failures gracefully so the journal still works. Keep the Walrus Memory agent ID and credentials server-side.

TATUM
Add a small, visible Sui onchain data panel using Tatum’s Sui RPC. Put the Tatum API key and network endpoint in server-side configuration. Make it clear when data is unavailable. Avoid decorative RPC calls that do not support the user’s prediction workflow.

NETWORK READINESS
Support separate Testnet and Mainnet configuration using environment variables. Do not hardcode the network throughout the app. Make it possible to test the entire memory flow on Testnet and later switch to Mainnet without changing product logic. Include a visible environment indicator in development, and make errors clear if Mainnet writes are not configured.

DESIGN AND QUALITY
Use a clean, distinctive sports-journal-inspired visual style that also works for markets and culture predictions. Make it responsive and accessible. Include loading, empty, success, and error states. Seed the UI with clearly labeled sample data for preview, but never represent sample data as real Walrus or blockchain data.

DELIVERABLES
Generate the first working app draft with:
- Dashboard
- New prediction form
- Prediction detail and resolution flow
- Searchable/filterable history
- Evidence-based insight component
- Walrus Memory integration boundary
- Tatum Sui RPC integration boundary
- Environment configuration example with placeholder values only
- README explaining setup and which credentials or services must be configured

Prioritize a complete, understandable end-to-end journal flow over extra features. Do not add betting, wagers, payments, public leaderboards, or social feeds.
